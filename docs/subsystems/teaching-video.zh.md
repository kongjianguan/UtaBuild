# 教学视频流水线

[English](teaching-video.md) | 中文

## 来源准备

[`prepare.mjs`](../../tools/teaching-video/prepare.mjs) 从 QQ Music 选择指定歌曲，获取原文与罗马音 QRC，调用 Rust [`teaching` 模块](../../cli/src/teaching.rs) 解密响应并获取 UtaTen Ruby，然后建立包含时间信息的项目文件。`fast-xml-parser` 读取 QRC 容器，`@applemusic-like-lyrics/lyric` 解析歌词时间信息。命令通过核对歌曲名称、歌手、专辑和时长选择完整的官方录音，再使用 `yt-dlp` 下载。专辑比较通过 `opencc-js` 规范化简体与繁体中文，来源证据保留原始元数据。FFprobe 检查录音时长和音轨。

项目保留来源中的原文片段时间区间与对应的日语罗马音区间。日语罗马音必须具备完整文本和时间；使用拉丁字母的歌词行通过来源中的原文片段与时间显示罗马音区域。全部来源 Ruby 范围必须通过包含空白的 Unicode codepoint 偏移量映射到完整原文。来源文本匹配会规范化出版标点，项目保留原文。来源标题、歌手、歌词 URL、Ruby URL、封面和录音时长随项目保存。准备命令保留原始来源响应和解析后的时间数据，便于核对生成的项目及其输入。命令保存 `project-source.json`，自动歌词校准成功后才生成 `project.json`。

## 自动歌词校准

[`calibrate.py`](../../tools/teaching-video/calibrate.py) 通过 `pnpm video:calibrate` 调用，使用 faster-whisper 与 CTranslate2 将给定日语歌词同选定录音进行声学匹配。默认的 `small` 模型使用已知文本进行匹配。命令将歌词片段划分为三个独立歌曲区段。在每个区段中，选择 22 秒以内规范化后有效文字最多的连续完整歌词，再包含前后各最多四秒的音频。每个模型窗口保持在 30 秒以内。模型文件缓存在已经忽略的 `work/whisper-models/` 目录中。

每个测量位置将原始 QRC 片段开始时间与测量得到的音频开始时间、已知文本的 token probability 配对。token probability 筛选给定文本，剩余误差和区段一致性检验测量所得的偏移。[`timing.py`](../../tools/teaching-video/timing.py) 负责定义 token probability、剩余误差、采样数量和区段一致性的标准。校准根据通过标准的测量位置估计一个共同偏移，并分别检查三个区段。符合标准的测量位置不足、偏移不一致或区段存在时间漂移时，校准终止。

校准后的项目必须包含 `lyric_offset_ms` 和绝对路径 `calibration_path`。有效歌词时间等于 `QRC 时间 + lyric_offset_ms`；正偏移使歌词延后显示。共同使用的渲染器在内存中为歌词行、原文片段和罗马音片段的区间应用该偏移。原始 QRC 区间、Ruby 关系和完整音频保留原有内容。

使用 `--output project.json` 时，校准在输出项目所在目录保存 `project.calibration.json` 与 `project.measurements.json`。报告记录偏移、原始测量位置、区段剩余误差、模型名称与哈希，以及音频和原始歌词数据的哈希。统计验收失败时，已经完成的声学测量仍可查阅。加载项目时检查音频与原始数据哈希，重新计算测量位置统计，并要求项目偏移与通过验收的报告一致。

## 教学内容

`teaching-input.json` 列出不同的演唱歌词及其来源 Ruby。当前 Agent 编写并复核对应的 `teaching.json`。每个条目保留来源中的原文措辞，并包含中文翻译、符合语境的词汇信息和表达讲解。渲染器使用经过 NFC 规范化并删除空白的文本匹配条目；重复演唱的歌词共享条目。词汇与表达必须出现在该条歌词中；读音遵循来源中的语境读音，释义和活用说明解释实际用法。

渲染器的 schema 负责定义字段。词汇卡片分别记录表达、读音、原形、词性、活用信息、释义和 JLPT 等级；必须提供的 `level` 字段在查阅来源无法支持等级标签时使用 `null`。渲染之前必须覆盖全部不同的演唱歌词。结构验证确认内容覆盖和字段有效性；Agent 对完整内容的复核确认语言准确性。

## 渲染

[`render.py`](../../tools/teaching-video/render.py) 验证项目与教学文件，加载指定的 CJK 字体，并使用 Pillow 合成画面。渲染器将画面发送到 FFmpeg，与选定音频一起编码为 MP4。命令声明负责定义布局、尺寸、颜色、时间范围选项和音频偏移语义。

原文、Ruby 与罗马音分别在各自的每一行中共享字体基线。每个字形保留字体相对于基线的纵向偏移。白色文字与逐步高亮使用相同的字形像素遮罩和位置。

词汇卡片和表达卡片使用 [`glass.py`](../../tools/teaching-video/glass.py) 实现的 Liquid Glass 材质。材质从每张卡片最终位置对应的实际封面背景取样，应用局部放大与模糊，并合成半透明色调、圆角边缘高光和柔和阴影。卡片文字区域保留自动强调颜色选择所使用的背景亮度上限。材质在每个教学分页合成时生成一次；预览和 MP4 画面复用相同的卡片背景。教学分页内容清单记录材质标识和圆角半径。

原文与罗马音高亮使用校准后的时间区间。演唱片段推进时，Ruby 保持附着于对应原文。词汇卡片和表达讲解随当前歌词变化。需要分页的内容分布在该句校准后的展示区间内。横屏与竖屏分别使用对应的尺寸与列数；完整导出以零音频偏移覆盖录音开始到结束的全部时间。非零音频偏移适用于选定片段。

渲染器在编码之前保存项目、教学、音频、背景、字体和校准报告的哈希，并在编码结束时检查这些输入是否保持一致。渲染器在 MP4 所在目录生成 `.render.json` 清单，记录开始时保存的输入哈希、校准路径与歌词偏移、输出哈希、合成设置、编码范围、画面数量、来源音频偏移、教学分页内容和原文字形位置。后续验证通过该清单确认导出时采用的确切输入和文件。

## 后期编辑

[`editor.py`](../../tools/teaching-video/editor.py) 通过 `pnpm video:edit` 调用，在本机回环地址提供编辑界面与媒体。FastAPI 验证请求，Pillow 提供实际渲染的预览。浏览器在画面上放置可选择的区域，提供直接编辑文字、拖动、坐标控件、组件删除、撤销、重做和分别保存的横竖屏位置。[`composition.py`](../../tools/teaching-video/composition.py) 同时构建预览和编码画面。

`EDIT_SCHEMA` 负责定义版本 2 编辑文件契约：显示文字的修改、删除标识和隐藏标识共享于两种画面比例。位置偏移、自动排版开关和场景排版记录分别保存。歌曲级组件使用固定标识；歌词组件包含来源行标识和所属区域。逐字片段修改保留来源时间区间。Ruby 范围通过修改后的 codepoint 边界映射，显示读音可以明确编辑。准备好的来源文件和教学文件保留原始内容。

选择与操作彼此独立。Shift 点击和框选用于预览中的选择；片段复选框和组件类型筛选可以选择当前片段、选定片段或者全部歌词片段。组件目录包含其他教学分页中的组件以及隐藏组件。移动操作为选中的最上层组件及其子组件应用相同位移；同时选中父组件和子组件时，位移只应用一次。原文片段默认联动选择对应的来源 Ruby，直接编辑文字时选择一个文字字段。多选移动、隐藏、显示、删除和恢复位移分别构成一次可以撤销的操作。

自动排版默认关闭。固定排版在文字、可见性和删除状态发生变化时保留未选中文字的位置、包含时间信息的文字基线、卡片矩形和分页归属。隐藏组件保留内容与手动位置，并且仍可通过组件列表选择。自动排版在当前画面比例的全部片段中测量可见的修改后文字，重新排列词汇卡片各列，并重新计算教学分页。关闭自动排版时，保存当前排版并保留手动位移。「排版一次」使用选定片段范围，清除这些片段在当前画面比例下的手动位移，保存完整排版，同时保留自动排版开关状态。它可以清除无效的场景位移，同时在撤销历史中保留出错状态。该明确的场景操作包含范围内的全部组件，独立于组件类型选择。普通文字按照组件宽度换行。缺少字形、排版记录无效、组件超出画面、内容超出可用高度或者分页阅读时间不足时，渲染器终止处理。

Pillow 对实际封面进行颜色量化，选择主要颜色。渲染器保留其色相，调整亮度，使颜色与经过暗化处理的封面背景最大亮度之间至少具备 4.5:1 的对比度。该颜色用于歌词、Ruby、罗马音高亮和教学强调文字。明确提供命令行颜色时，使用指定颜色。

编辑目录将保存的编辑内容绑定到选定项目、教学文件、封面、字体设置、校准报告和歌词偏移。片段跳转、预览和导出共同使用校准后的歌词时间。服务拒绝活动来源文件或校准报告发生改变后的请求。每次导出分别保存编辑快照、MP4、渲染清单、日志和验证证据。清单将编辑路径与哈希同媒体输入哈希一起记录；验证流程还原经过编辑的合成结果，并检查对应快照。导出界面在验证成功后提供产物下载。

## 失败行为

准备流程要求使用新目录或空目录。输出目录已经包含文件、无法确认歌曲身份、缺少必需的歌词或读音来源、来源文本无法匹配、缺少罗马音时间信息、录音时长与选定歌曲不一致，或自动校准失败时，准备流程终止。校准要求使用独立且尚未使用的输出项目与证据路径。项目或教学文件无效、缺少校准证据或证据不一致、校准后的演唱区间超出录音、歌词覆盖不足、缺少字形、布局无法容纳内容、教学分页展示时间不足、完整录音采用非零音频偏移、输出文件已经存在、编码期间输入改变，或编码器发生错误时，渲染流程终止。再次导出之前，需要修正对应的来源、内容或输出参数。

## 验证

[`verify.py`](../../tools/teaching-video/verify.py) 通过 `pnpm video:verify` 调用，根据渲染清单和输入哈希验证 MP4。验证器将校准报告哈希与歌词偏移同清单比较，重新计算三个区段的测量统计，并在校准后的歌词时间采样画面。`--require-full-song` 要求开始时间为零，包含完整录音所需的全部画面，并使用零音频偏移。验证流程解码整个文件，检查媒体元数据，将每个已经展示的教学分页与选定高亮时刻的编码采样画面同预期合成结果比较，并按照选定来源音频与偏移比较成品音频采样。对于采样原文字符，验证器根据已经记录的行内基线独立还原字体的实际字形像素，并检查编码画面中的字形位置。报告包含字形采样数量和实际测量的纵向偏移。

证据目录包含 `verification.json` 和采样画面文件。`lyric_alignment` 部分保留通过验收的校准报告、偏移、路径与哈希。报告用 `song_scope: full` 标识完整录音，用 `song_scope: clip` 标识选定区间；歌词场景与分页数量覆盖实际编码范围。完整歌曲产物需要同时满足 `status: passed` 和 `song_scope: full`。

共享歌词行为变更还需要遵守[核心歌词流水线检查](../../AGENTS.md)，并检查完整 fixture JSON。[用户教程](../user/teaching-video.zh.md) 负责执行步骤，[项目 Skill](../../.agents/skills/generate-teaching-video/SKILL.md) 负责可复用的 Agent 工作流程。
