# 翻译规则

[English](translation-rules.md) | 中文

本规则约束双语文档配对两侧之间的翻译。两种语言同等有效（见 [README.zh.md](README.zh.md)）；正在修改的一侧是本次更新的源文件。规则同样约束人和 agent。规则等级遵循 RFC 2119：**MUST** 和 **MUST NOT** 是评审或门禁阻断条件；**SHOULD** 偏离时需要说明理由；**MAY** 表示可自行决定。

## 忠实性

- 对应文件 **MUST** 表达源文件所表达的内容：不得增加或遗漏行为、前置条件、警告、版本声明或示例。
- 对应文件 **SHOULD** 是目标语言中自然的技术写作，而不是逐词直译。翻译含义，在目标语言需要时重组句子，并保持作者的语体。
- 如果直译会不自然，应翻译习语的含义。不要为了保留源语言隐喻而牺牲清晰度。

## 语体

- 参照 [style-samples.md](style-samples.md) 中最近的人工确认样例。英文使用简洁、专业的开发者文体；中文使用准确、克制的技术文体。
- 以目标语言技术作者的方式重述，同时保留源文件的每个分句。自然流畅不能成为增加或遗漏要求的理由。
- 当目标语言会掩盖责任时，明确写出实际执行者。优先使用已有的工程术语，不要生造直译词。
- 按语义单元拆分长段落。当配对结构契约不编码段落边界时，段落边界可以不同于源文件。
- 翻译成中文时，必要时在首次出现的类别名后附英文注释。目录、文件、命令、标识符和 API 引用保持英文 code 格式。

## 结构保持

配对验证器检查标题深度、围栏代码块、表格维度、列表形状和语义链接。配对文件 **MUST** 在以下方面一一对应：

- 标题层级、顺序和深度；
- 列表类型、编号、数量和顺序；
- 表格列数、行数和行顺序；
- 围栏代码块的信息字符串和正文按字节一致，包括注释；
- 命令、参数、路径、键、事件名、API 名和版本号等行内 code 片段；
- 相对链接及精确的 query 或 fragment 后缀。指向活跃双语语料的链接，英文侧使用 `.md` 目标，中文侧使用 `.zh.md` 目标。外部 URL、图片和纯页内 fragment 保持不变。链接文本翻译。

当仓库的 Markdown 约定要求时，每个段落保持一行、文件只有一个结尾换行，并避免无意的空白变化。语言切换行是明确允许跨语言变化的例外。

## 术语

- 翻译前加载 [terminology.md](terminology.md)。所有已列术语 **MUST** 遵循其表格和禁止译法。
- 对中文目标，未列出的技术术语 **MAY** 使用可靠中文工程资料中已经确立的译法。没有可靠先例时，保留英文，并在「待定术语」中记录证据和建议译法。
- 对英文目标，使用确立的英文术语。如果没有无歧义的对应词，保留源术语并加最短必要释义，同时列为待定术语。
- 已决定的术语应在同一变更或明确链接的后续变更中写入 `terminology.md`。不要在正文中悄悄创造与术语表冲突的译法。

## 中文排版

以下规则约束中文正文；英文侧遵循仓库常规 Markdown 约定：

- **MUST** 在中文与拉丁字母之间、中文与数字之间各留一个半角空格：`每个 plugin 注册 3 个 tool`。
- **MUST** 在中文正文中使用全角中文标点：`，。：；？！（）「」`。半角标点保留在 code、完整英文原句和 `3.5`、`1,024` 等数字中。
- 当句子更清楚时，优先使用冒号、句号、逗号或括号替代破折号。
- 中文并列项目使用顿号（、）。
- **MUST NOT** 使用全角数字或全角拉丁字母。专有名词和标识符使用规范大小写。
- 面向读者的说明使用「你」，不使用「您」。
- code 中的英文保持原样；不要在字面路径、命令、参数或标识符后重复添加翻译。
- 中文标点前不加空格，左括号后不加空格，右括号前不加空格。
- 同一列表中的项目保持结尾标点一致。完整列表项不要以逗号结尾。

## 评审

确认配对一致前，先不看源文件独立阅读译文，再逐分句对照两侧。检查是否遗漏或增加事实、执行者、情态、否定、条件、范围、数字、代码、链接、术语、标点和首次出现注释。将待定术语记录下来，不要在正文中静默决定。

sidecar 只记录对精确文件内容的机械确认，不是评审者完成或通过语义检查清单的证据。
